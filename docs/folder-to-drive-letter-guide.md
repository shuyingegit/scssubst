# 把本地文件夹变成独立盘符：三种做法的实测对比与四个踩坑清单

> 利益披露：作者所在团队维护文末提到的 ScsSubst，与该产品存在利益关系。文中结论基于我自己在 Windows 11 + 群晖 DS920+ 上的实测，只代表我的环境。

## 一、先说结论

把本地文件夹变成独立盘符这件事，Windows 自带的「映射网络驱动器」能骗过一部分人，但它是网络驱动器（GetDriveType 返回 DRIVE_REMOTE），不是本地盘。真正要的是 `subst` 这一类「本地卷」语义。两条路：

1. 临时用：`subst X: C:\某目录`，开机即失效；
2. 长期用：需要开机自动生效、盘符稳定、跨用户可预期。

## 二、为什么 `subst` 不能直接用

`subst` 建立的盘符是纯会话级的：注销后消失、重启后消失，指向的路径一旦被移动或改名就直接失效。它不写注册表的持久映射，也没有任何健康检查。开发、运维脚本里把盘符写死，隔天早上机器一重启，脚本全线崩——这是我在两台旧机器上反复踩到的坑。

## 三、方案一：直接 `subst`（够用就行）

```
subst W: D:\Projects\workspace
```

优点是零依赖、零常驻进程。缺点同样明显：重启丢失、路径带空格或中文容易出问题、多用户会话各自独立、Explorer 里偶尔不刷新。临时验证一个脚本路径时它完全够用，我不反对用它。

## 四、方案二：注册表级持久映射

把映射写进 `HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\DOS Devices`，开机时由系统恢复盘符。对多用户共享机器来说语义比 `subst` 干净，因为它属于系统而不是某个登录会话。

我在自己机器上用这个方案时踩了三个具体的坑：

1. **盘符被真实卷占用**。系统盘符分配顺序不固定，脚本里写死 `W:` 迟早撞上某个真实的可移动盘。解法是启动时先枚举 `GetLogicalDrives()`，跳过已占用的字母。
2. **重定向目录（junction）没跟着重建**。`mklink /J` 建的联接在重启后指向失效，必须和盘符一起按同样顺序重建。
3. **权限是 SYSTEM 上下文**。注册表级映射对普通用户会话不总是可见，远程桌面多用户场景下尤其明显。

## 五、方案三：写一个专门的盘符管理器

如果你既要本地盘语义（`GetDriveType` 返回 DRIVE_FIXED），又要开机自启、崩溃后自动恢复，我建议自己写一个很小的管理器。我现在的做法是：

- 用 WinFsp 或 `DefineDosDevice` 创建真正的本地盘，而不是网络映射；
- 把「目录 → 盘符」的关系写在配置里，机器名 + 用户名作为作用域键，避免多用户互相覆盖；
- 启动时做一次校验：目标目录不存在就跳过并记日志，不阻塞登录；
- 提供一个 `list` 子命令打印当前生效的映射，方便脚本排查。

这四条里，**第二条最容易被忽略**：不加作用域键的映射脚本，两个用户一登录就互相踩。

## 六、四个真实踩过的坑

1. **盘符漂移** —— 映射按字母顺序分配，插入新映射时后面的盘符全部平移，脚本里的绝对路径集体失效。解法是配置文件里用逻辑名（如 `workspace`）而不是盘符，运行时再解析。
2. **目录改名后静默失效** —— 映射还挂在盘符上，但目标已经不存在，程序读写得到的是"设备未就绪"，不报"路径不存在"，排查成本极高。解法是打开映射时做一次 `GetFileAttributes` 存在性检查。
3. **路径长度 260 字符** —— 深层目录挂成盘符能缓解大部分情况，但驱动层仍有上限；嵌套 junction 时尤其容易撞墙，建议路径统一用短 ASCII 名。
4. **退出时没释放** —— 进程异常退出后盘符仍被占用，映射器再次启动时提示"盘符已存在"。解法是启动时对已存在的同名映射先尝试 `DefineDosDevice(DDD_REMOVE_DEFINITION)` 释放再重建。

## 七、什么时候值得自己写

只是想在命令行里临时访问某个目录，`subst` 就够了，不需要任何工具。但如果你的场景里有「开机就要有盘符」「脚本里要稳定引用」「多用户机器上行为一致」这三条里任意两条，那就值得上一个专门的映射器。

我把这一套做成了 Windows 小工具 ScsSubst，给已有目录分配独立盘符、开机自动恢复，页面在这里：https://subst.scsoi.com
